# rare_sample_efficient — 高效稀有事件采样器

多线程随机采样程序：从均匀分布 `u ∈ (0, 1]` 生成 `S = -ln(u)`（指数分布），
映射到标准正态分位 `x = Φ̄⁻¹(u) = Φ⁻¹(1-u)`，持续寻找最稀有的样本，
直到 `|x| >= 10σ` 为止。

> **双边口径（重要）**：`x` 是**带符号**的标准正态样本 `x ~ N(0,1)`，
> 因此分档、纪录、达标全部按 `|x|`（±kσ）判定。
> 只比较右尾阈值 `S >= SH[k]` 的旧写法会把左尾（`x < -1σ`，占比 15.87%）
> 错算进 `[0,1)σ` 档，使该档显示成 `Φ(1) ≈ 84.13%`（正确值 `2Φ(1)-1 ≈ 68.27%`）。
> 修正方案见「数学原理」：双边坐标 `y = -ln(min(u,1-u))` + 左尾阈值 `LH[k]`。

## 数学原理

### 1. 均匀数 → 带符号正态分位

对 `u ~ U(0, 1]`，`S = -ln(u)` 服从标准指数分布：`P(S > s) = e^{-s}`。
取 `x = Φ̄⁻¹(u) = Φ⁻¹(1-u)`，由于 `1-u` 仍是 `(0,1]` 上的均匀数，
`x` 就是**标准正态 `N(0,1)` 的样本，可正可负**：

- `u <= 1/2` ⟺ `x >= 0`（右尾）：`S = -ln(u) >= ln2`，`x` 越大 `S` 越大；
- `u > 1/2` ⟺ `x < 0`（左尾）：`S = -ln(u) < ln2`，`x → -∞` 时 `u → 1`、`S → 0`。

也就是说，**光看 `S` 大小无法判断"多少 σ"**：左尾越极端，`S` 反而越接近 0。
这正是旧版分档出错的根源——`S < SH[1]` 并不等于 `|x| < 1σ`，它同时包含
`x ∈ [0,1)`（占比 34.13%）和 `x ∈ (-∞,0)`（占比 50%）。

### 2. 双边坐标与 ±kσ 上下界

按 `|x|` 分档需要同时看两条尾。定义**双边尾坐标**

```
y = -ln(min(u, 1-u))  >=  ln2 = SH[0] = LH[0]
```

它把两条尾折叠成一个量：

```
|x| >= kσ   ⟺   min(u, 1-u) <= Φ̄(k)   ⟺   y >= SH[k],   SH[k] = -ln Φ̄(k)
```

所以左右尾共用同一张阈值表 `SH`。若要用 `S = -ln(u)` 表述，两条尾的阈值不同：

| 事件          | 判据（`S = -ln u`） | 阈值                                  |
|---------------|---------------------|----------------------------------------|
| 右尾 `x >= +kσ` | `S >= SH[k]`      | `SH[k] = -ln Φ̄(k)`（右尾阈值）        |
| 左尾 `x <= -kσ` | `S <= LH[k]`      | `LH[k] = -ln Φ(k) = -ln(1 - Φ̄(k))`（左尾阈值） |

**档位 k 的上下界**：`|x| ∈ [k, k+1)σ` 等价于

```
SH[k] <= y < SH[k+1]
```

即"下界由 ±kσ 给出、上界由 ±(k+1)σ 给出"（`k = 0` 的下界是 `y >= ln2`，
末档 `k = NBINS` 的上界是 ∞）。热路径上只做一次 `y >= SH[i]` 比较，
但四个边界（`+kσ`、`+(k+1)σ`、`-kσ`、`-(k+1)σ`）都已参与判定，
左尾的小概率不会再被算进右尾的区间。

双边理论占比：

```
P(|x| ∈ [k,k+1)) = 2(Φ̄(k) - Φ̄(k+1)) = 2(Φ(k+1) - Φ(k)),   末档 = 2Φ̄(NBINS)
```

目标 `10σ` 的双边概率为 `P(|x| >= 10) = 2Φ̄(10) ≈ 1.52e-23`（`SH[10] ≈ 53.23`，
单边 `Φ̄(10) ≈ 7.62e-24` 只是它的一半；顺带一提，`7.62e-24` 现在正好是
左尾阈值 `LH[10] = -ln Φ(10)`）。

### 3. 106 位均匀数

用 xoshiro256++ 产生两个 53 位整数拼成 106 位：

```
U = u_hi * 2^53 + u_lo ∈ [0, 2^106)
u = (U + 1) * 2^-106 ∈ (0, 1]
```

右尾（`u <= 1/2`）与左尾（`u > 1/2`）各自精算（`log1p` 处理尾项，无相消误差）：

```
右尾：S   = -ln u   = 106·ln2 - ln(U + 1)
左尾：y_L = -ln(1-u) = 106·ln2 - ln(c),   c = 2^106 - U - 1 = (2^53-1-u_hi)·2^53 + (2^53-1-u_lo)
双边坐标：y = max(S, y_L) = -ln(min(u, 1-u))
```

`u` 直接对补数 `c` 取对数，避免 `u → 1` 时算 `1-u` 的灾难性相消。

分辨率上限：右尾最小可表示的 `u = 2^-106`（`U = 0`），左尾最大 `u = 1`（`U = 2^106-1`，
此时 `1-u = 0`，代码把坐标封顶到 `y_max`）。两端都对应
`y_max = 106·ln2 ≈ 73.47`，即 `|x|` 最大约 **11.84σ**（双边尾概率 `2^-105`）。
由于 `SH[12] ≈ 75.41 > 73.47`，`[12, ∞)σ` 档**永远为 0**；需要这一档请把
`NBINS` 调到 11。

### 4. 快速拒绝

`Y_upper_from_hi(u_hi)` 只用高位块估算 `y` 的**上界**（右尾
`53·ln2 - ln u_hi`，左尾 `53·ln2 - ln(2^53-1-u_hi)`）。上界低于 1σ 阈值
（留 `REJECT_MARGIN = 1e-15` 舍入余量）就判定 `|x| < 1σ`，直接归入 `[0,1)σ`
档，约 **68.27%** 的样本走此路径，省掉完整的对数计算。

上界必须真的是上界，否则快速拒绝会误杀稀有样本。另外注意：`S < SH[1]` 只说明
**右尾** `x < 1σ`，它同时包含整个左半轴（`x < 0`，占 50%）；把这些样本统统
记进 `[0,1)σ` 档、而不区分左尾 `x ∈ (-1,0)` 与右尾 `x ∈ [0,1)`，
正是修正前的 bug——档位判据必须是双边坐标 `y < SH[1]`。

**字段说明**：

- `y`：双边尾坐标 `-ln(min(u,1-u))`，**越大越稀有**（`|x| >= kσ` ⟺ `y >= SH[k]`）；
  旧版的 `S = -ln u` 对左尾样本反而趋近 0，无法直接比较。
- `x`：带符号分位，**左尾为负**（`x = ±x_from_s(y)`）。
- `稀有度 log10 P`：该纪录的双边尾概率对数
  `log10(2Φ̄(y)) = (ln2 - y)/ln10`。
- `分级统计`：
  - `环形分布`：`[a,b)σ:N` 表示 `|x|` 落在该区间的样本数（左右尾合计）。
  - `稀有度 log10 P`：每个区间的理论概率以 10 为底的对数
    （`P = 2(Φ̄(k) - Φ̄(k+1))`，末档 `2Φ̄(NBINS)`），值越小越稀有。
  - 每类分布压缩为 2 行、bin 间用 `|` 分隔，便于纵向对比不同快照。
  - 线程本地分箱每 `FLUSH_INTERVAL = 65536` 个样本才并入全局，
    所以**很早的快照里计数可能为 0 或偏小**（`当前总抽样数` 也是按 1024 批量累加的），
    属于正常现象，样本多了就对齐了。
- **两个时间的区别**：
  - `纪录时间`：稀有样本实际产生的时刻（`Record::when`）；
  - `写入时间`：本条日志落盘的时刻。

  `[新纪录]` 两者近似相同（发现后立即写）；`[每分钟]` 快照两者可相差约
  60 秒——快照里的 y/x/统计是"写入时刻"的最新状态，而纪录时间始终是那条
  纪录诞生的时刻。

**校验方法**：`环形分布` 中各档计数 / 总抽样数应趋近「阈值表与理论概率」一节的比例，
例如 `[0,1)σ ≈ 0.6827`、`[1,2)σ ≈ 0.2718`、`[2,3)σ ≈ 0.0428`，且与同行的
`稀有度 log10 P` 一致（`10^{log10 P}` 即理论概率）。反向自查：把每档计数按
`x <= -kσ`（即 `S <= LH[k]`）拆成左右两份，两侧应约各占一半。
若偏差过大，优先检查 `thresholds.cpp` 的 SH/LH 表与 `scompute.hpp`。

## 并发设计（排查并发问题必读）

所有共享状态集中在 `shared_state.hpp/.cpp`：

| 状态              | 保护方式             | 说明                          |
|-------------------|----------------------|-------------------------------|
| `g_best`          | `g_mutex`            | 当前最稀有纪录                |
| `g_best_y`        | 原子 double          | `g_best.y` 的无锁镜像，热路径快筛 |
| `g_has_new_record`| 原子 bool + `g_mutex` | 在锁内置位，防止丢失唤醒      |
| `g_stop` / `g_reached` | 原子 bool      | 停机 / 达标标志               |
| `g_total_samples` | 原子计数             | 每 1024 样本批量累加          |
| `g_ring`             | `g_bin_mutex`      | 全局环形分箱计数              |
| 线程本地 `LocalBins` | 无锁（线程私有）  | 每 65536 样本刷入全局         |

**锁顺序约定**：`g_mutex → g_bin_mutex`，不可反向（避免死锁）。

### 线程模型

```
main
 ├─ worker[0] ── sample_loop(seed + 0·φ)   采样 + 更新纪录
 ├─ worker[1] ── sample_loop(seed + 1·φ)   （每个线程独立 RNG 流）
 ├─ ...
 └─ recorder ── record_loop(outfile)        等 g_cv，写日志
```

停止流程：任一 worker 发现 `|x| >= 10σ`（`y >= SH[10]`）→ 置 `g_stop` + `g_reached`
→ 所有 worker 退出循环 → `main` join 后再置 `g_stop` 唤醒 recorder →
recorder 写最终快照。

## 常见问题排查

**Q: 为什么 `[0,1)σ` 档不再是 84%，而是 68.27%？**
因为它现在表示 `|x| < 1σ`（双边），而不是 `x < 1σ`。`x < 1σ` 把左尾
`x ∈ (-∞,-1σ]`（15.87%）也算进去了，那是旧版的 bug。参考值见
「阈值表与理论概率」。

**Q: 为什么纪录里的 `x` 有时是负数？**
`x` 是带符号正态分位；`x < 0` 表示这条纪录来自左尾，它的 `y = -ln(1-u)` 同样很大。
双边口径下 `x = -4.2` 与 `x = +4.2` 一样稀有（`P ≈ 2.7e-5`）。

**Q: 为什么 `[12, ∞)σ` 档永远是 0？**
106 位均匀数能表示的最大双边坐标是 `106·ln2 ≈ 73.47`（`|x| ≈ 11.84σ`），
而 `SH[12] ≈ 75.41`。把 `NBINS` 改成 11 即可让最后一档有样本。

**Q: 编译报错 `'logl' is not a member of 'std'`？**
Ubuntu 的 libstdc++ 不在 `std` 命名空间提供 `logl`/`erfcl`/`log1pl` 等 C 包装
函数。本项目统一使用 `std::log`/`std::erfc`/`std::log1p` 的 long double 重载
（C++ 标准保证存在），请确认用的是最新版源码。

**Q: 统计偏差大（环形分布明显偏离理论概率）？**
1. 检查启动时打印的 `SH`/`LH` 表是否与 README 表格一致；
2. `Y_upper_from_hi` 必须返回**上界**（否则快速拒绝会误杀稀有样本）——
   见 `scompute.hpp` 注释；上界只对样本所在的那条尾有效，统一入口请用
   `Y_upper_from_hi()`，不要自己挑 `S_from_hi`/`S_left_from_hi`；
3. `S_from_two` / `S_left_from_two` 中 `log1p(delta)` 不可简化为 `delta`
   （hi 小时误差达 0.3）；
4. 左尾必须走补数 `c = 2^106 - U - 1` 的对数，不能算 `1 - u`（`u → 1` 时相消）。

**Q: 输出文件里中文乱码？**
Windows 控制台默认 GBK，UTF-8 源文件中文在 `Get-Content` 下可能显示异常。
用 `Get-Content -Encoding UTF8` 查看，或在代码中改用英文输出。

**Q: 程序长时间不退出？**
双边 10σ 事件概率约 `1.5e-23`，单线程每秒约 2000 万样本，理论期望需要极长时间。
这是设计使然（分布式跑批场景）。可用 Ctrl+C 手动停止，已写入的日志不丢失。

**Q: 想改目标 σ？**
改 `config.hpp` 的 `TARGET_SIGMA` 和 `NBINS`（`TARGET_SIGMA` 必须是整数，
且 `NBINS >= TARGET_SIGMA`，两处都有 `static_assert` 兜底）。
`SH`/`LH` 表由 `erfc` 启动时计算，无需手动更新。

**Q: 如何验证单线程结果可复现？**
固定 seed 且 `nthreads=1` 时，样本序列完全确定。多线程时各线程 RNG 流独立，
但调度顺序不定，日志中"该样本是第几个"等字段可能不同。

## 已修复的历史 bug（供对照排查）

1. **阈值表发散**：旧版 `s_from_x` 用渐近级数 `1 - 1/x² + 3/x⁴ - ...`，
   在 x=1、2 处发散，1σ 阈值算出负值。已改用 `erfc` 精确计算。
2. **快速拒绝方向错误**：`S_from_hi(0)` 旧版返回下界，破坏"上界才能安全
   拒绝"的不变量。已改为返回 `106·ln2` 上界。
3. **S 精算误差**：`S_from_two` 旧版用 `-δ` 近似 `-ln(1+δ)` 且漏了 `+1`，
   hi 小时误差达 0.3σ 档位。已改用 `log1p` 精确计算。
4. **丢失唤醒**：`g_has_new_record` 旧版在锁外置位，记录线程可能错过通知。
   已移入 `g_mutex` 临界区。
5. **计数丢失**：线程退出时最后不足 1024 个样本未累加到
   `g_total_samples`。已补上 `idx % TOTAL_BATCH` 的尾数刷新。
6. **分档缺上界、漏左尾（本次修复）**：旧版分档只用右尾下界
   `S >= SH[i]`，于是 `[0,1)σ` 实际统计的是 `x < 1σ`（84.13%），把左尾
   `x <= -1σ` 吞了进去；纪录与达标判定也只看右尾 `S`，左尾的极端样本
   （`|x|` 可以更大，但 `S → 0`）永远不会成为纪录、也不会触发停止。
   已改为双边坐标 `y = -ln(min(u,1-u))` + 上下界判定
   （`SH[k] <= y < SH[k+1]`，即 ±kσ/±(k+1)σ 四个边界都参与），
   并新增左尾阈值表 `LH[k] = -ln Φ(k)`（`S <= LH[k]` ⟺ `x <= -kσ`）、
   左尾精算 `S_left_from_two`（对补数取对数）与左尾上界 `S_left_from_hi`。
   修复后 `[0,1)σ = 68.27%`，左右尾各占每档一半。
7. **`LN2` 字面量精度不足**：`0x1.62e42fefa39efp-1L` 只有 53 位尾数，
   给 `106·ln2` 引入约 `2.4e-15` 的绝对误差（会让边界样本偶发串档）。
   已改为 64 位尾数的 `0x1.62e42fefa39ef357p-1L`（与 `std::log(2.0L)` 同值）。
8. **`x_from_s` 在 0σ 附近失效**：旧版 4 步牛顿用的是渐近导数 `x + 1/x`，
   在 `x → 0` 时完全失真，只能靠 `if (x < 1) x = 1` 硬夹——于是任何
   `y < SH[1]` 的纪录都会显示成 `x = 1`。已改为二分求解，并正确处理
   `y <= ln2 ⇒ x = 0`。
9. **快速拒绝的舍入余量**：上界自身带 `~1e-18` 舍入误差，理论上可能把
   恰好压在 1σ 边界外的样本判成 `< 1σ`。现在拒绝判据为
   `y_ub < SH[1] - REJECT_MARGIN`（`1e-15`），代价可忽略。
